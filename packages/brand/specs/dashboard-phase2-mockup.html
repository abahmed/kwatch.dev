payments-api keeps crashing: it ran out of memory

Why it happened

payments-api used more memory than it is allowed and was stopped (OOMKilled), then started again, over and over. Its limit is 256Mi and it passes that when the nightly export starts.

What to do

Give it more memory, then watch it for a few minutes. First check what it may use today:

kubectl -n payments get deploy payments-api -o jsonpath='{.spec.template.spec.containers[0].resources.limits.memory}'

Then raise the limit:

kubectl -n payments set resources deploy/payments-api --limits=memory=512Mi

No ingress controller

Your cluster has no ingress controller, so kwatch can't share the dashboard yet. An ingress controller is what lets traffic from outside reach your cluster. Install one (ingress-nginx is a common choice), then try again. You can still use "Turn on, local only" now.

No way to get a certificate

kwatch won't share the dashboard without https, and I couldn't find a way to get a certificate. The easiest way is cert-manager with a ClusterIssuer. Set that up, then try again. Until then, use "Turn on, local only".
